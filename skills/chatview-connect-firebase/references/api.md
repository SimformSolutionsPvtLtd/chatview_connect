# chatview_connect API reference

Verified against the `chatview_connect` source. Import
`package:chatview_connect/chatview_connect.dart`. `ChatUser`, `Message`,
`MessageStatus`, `ChatListItem`, `PinStatus`, `MuteStatus`,
`UserActiveStatus`, `ChatRoomType` and `TypeWriterStatus` come from
`chatview_utils`, which `package:chatview/chatview.dart` re-exports.

## ChatViewConnect

| Member | Behavior |
|---|---|
| `ChatViewConnect.initialize(ChatViewCloudService.firebase, {chatUserConfig, cloudServiceConfig})` | Creates the singleton. Only the first call has an effect |
| `ChatViewConnect.instance` | The singleton. Asserts when not initialized |
| `setCurrentUserId(String)` | Asserts non-empty. Use the Firebase Auth uid |
| `resetCurrentUserId()` | Clears it (sign-out) |
| `currentUserId` | `String?` |
| `getChatListManager({required scrollController, sortEnable = true, chatSorter, includeEmptyChats = true, includeUnreadMessagesCount = true})` | `ChatListManager`. Starts listening to the user's rooms immediately |
| `getChatRoomManager({required scrollController, lazyCreateChat = false, config, chatRoomId, currentUser, otherUsers, chatRoomType, groupName, groupProfile})` | `Future<ChatManager>`. Pass `chatRoomId` for an existing room, or `currentUser` + `otherUsers` + `chatRoomType` to find or create one. A one-to-one pair reuses an existing room. Anything else throws `Invalid parameters` |

## ChatManager (extends ChatController)

All `ChatController` members from chatview apply. Extra members:

| Member | Returns | Notes |
|---|---|---|
| `chatRoomId` | `String` | Asserts it is set |
| `otherActiveUsers` | `List<ChatUser>` | Members who haven't left or been removed |
| `onSendTap(message, replyMessage, messageType, {useAutoGeneratedId = false})` | `Future<Message?>` | Builds the `Message` (uuid id, current user), adds it locally, uploads an image, writes it with status `delivered`. `null` if the room isn't ready. With `useAutoGeneratedId` Firestore chooses the id |
| `onSendTapFromMessage(Message, {useAutoGeneratedId})` | `Future<Message?>` | Same, for a `Message` you built (for example `MessageType.custom`) |
| `onMessageTyping(TypeWriterStatus)` | `Future<void>` | Writes the typing status |
| `onMessageRead(Message)` | `Future<void>` | Writes `message.status`. Pass a copy with `MessageStatus.read` |
| `onLoadMoreData(direction, message, {batchSize = 10})` | `Future<void>` | For `ChatView.loadMoreData`, only with `enablePagination` |
| `loadOldReplyMessage(messageId, {batchSize = 10, sortBy, sortOrder})` | `Future<void>` | Loads the messages around an old reply with `replaceMessageList` |
| `onUnsendTap(Message)` | `Future<bool>` | Deletes the message and its image |
| `userReactionCallback(Message, String emoji)` | `Future<void>` | Writes the reactions of the message |
| `updateGroupChat({required ChatRoomDisplayMetadata displayMetadata})` | `Future<bool>` | New group name and photo. Doesn't check the room is a group |
| `addUserInGroup({required userId, required Role role, required bool includeAllChatHistory, DateTime? startDate})` | `Future<bool>` | The new user sees history from `startDate` (or all of it) |
| `removeUserFromGroup({required userId})` | `Future<bool>` | Sets `MembershipStatus.removed`. Deletes the group when no member is left |
| `leaveFromGroup()` | `Future<bool>` | Sets `MembershipStatus.left` for the current user. Deletes the group when no member is left |
| `updateUserActiveStatus(UserActiveStatus)` | `Future<bool>` | Presence |
| `createChat(String userId)` | `Future<String?>` | One-to-one room id (existing or new), `null` on failure |
| `createGroupChat({required groupName, required Map<String, Role> participants, groupProfilePic})` | `Future<String?>` | Room id |
| `getUsers()` | `Future<Map<String, ChatUser>>` | Every document of the users collection, current user included |
| `deleteChat(String chatId)` | `Future<bool>` | For every member, including media |
| `dispose()` | `void` | Cancels streams, then `ChatController.dispose()` |

Room methods return `false` or `null`, or do nothing, until the room's
streams run (`lazyCreateChat` before the first send).

## ChatListManager (extends ChatListController)

All `ChatListController` members from chatview apply (see
`chatview-chat-list`), except that the manager keeps `chatList` in sync with
Firestore. Extra members:

| Member | Returns | Notes |
|---|---|---|
| `createChat(String userId)` | `Future<String?>` | Same as on `ChatManager` |
| `createGroupChat({required groupName, required participants, groupProfilePic})` | `Future<String?>` | Same as on `ChatManager` |
| `pinChat(ChatStatusRecord<PinStatus>)` | `Future<void>` | For `ChatMenuConfig.pinStatusCallback` |
| `muteChat(ChatStatusRecord<MuteStatus>)` | `Future<void>` | For `ChatMenuConfig.muteStatusCallback` |
| `deleteChat(String chatId)` | `Future<bool>` | For every member, including media |
| `updateUserActiveStatus(UserActiveStatus)` | `Future<bool>` | Presence |
| `getUsers()` | `Future<Map<String, ChatUser>>` | As on `ChatManager` |
| `dispose()` | `void` | Disposes the controller and cancels the Firestore subscription |

Each `ChatListItem` it builds has `id` = room id, the room's `name` and
`imageUrl`, `lastMessage`, `unreadCount` (when `includeUnreadMessagesCount`),
`userActiveStatus` (taken from the other user in one-to-one rooms, `offline`
for groups), `typingUsers` (members whose typing status is not `typed`) and
`settings` (pin, mute).

## Configuration classes

| Class | Fields |
|---|---|
| `ChatUserConfig` | `idKey`, `nameKey`, `profilePhotoKey`: field names of the user documents (defaults `id`, `name`, `profilePhoto`) |
| `FirebaseCloudConfig` | `databasePathConfig` (`FirestoreChatDatabasePathConfig(userCollectionPath:)`: document path that holds the users collection), `collectionNameConfig` |
| `FirestoreChatCollectionNameConfig` | `users` (`users`), `chats` (`chats`), `messages` (`messages`), `userChats` (`user_chats`). No `/` and not empty |
| `ChatControllerConfig` | `syncOtherUsersInfo` (required), `chatRoomMetadata`, `onUsersActivityChange`, `onChatRoomDisplayMetadataChange` |
| `ChatRoomMetadata` | `chatRoomType`, `currentUser`, `otherUsers`, `groupName`, `groupPhotoUrl` |
| `ChatRoomDisplayMetadata` | `chatName`, `chatProfilePhoto` |
| `ChatRoomParticipant` | `userId`, `chatUser`, `role`, `membershipStatus`, `typingStatus`, `userActiveStatus`, `pinStatus`, `muteStatus` |

`syncOtherUsersInfo: true` (also the default when no config is passed) keeps
other users' name and photo up to date in the controller.

## Enums

- `ChatViewCloudService.firebase`
- `Role.admin`, `Role.user` (a missing or empty value reads as `admin`)
- `MembershipStatus.member`, `.removed`, `.left`
- `MessageSortBy.createAt`, `.updateAt`, `.none` and `MessageSortOrder.asc`,
  `.desc` (for `loadOldReplyMessage`)
- `ChatSortBy.newestFirst`, `.none`

## Firebase layout

Collections: `users` (written by the app, read by the package), `chats` with
a `messages` subcollection and a `users` subcollection of per-room member data
(role, membership, typing, pin, mute), and `user_chats` (presence and the
user's room list). Media is stored under `chats/{chatId}/images/`. The full
schema:

- <https://github.com/SimformSolutionsPvtLtd/chatview_connect/blob/master/doc/firebase/firebase-database-schema.md>
- <https://github.com/SimformSolutionsPvtLtd/chatview_connect/blob/master/doc/firebase/firebase-storage-structure.md>

Message documents store the timestamp in `createdAt`. A message whose
`createdAt` can't be read is skipped when loading.
